# Zero-Shot AI Text Detection Methods

Zero-shot methods detect machine-generated text without needing a task-specific labeled classifier. They exploit intrinsic statistical differences in how language models generate text (e.g. probability distribution curvature, perplexity, entropy) versus human writing.

---

## 1. Binoculars (State-of-the-Art Zero-Shot)

* **Repository:** [ahans30/Binoculars](https://github.com/ahans30/Binoculars)
* **Paper:** *Spotting LLMs With Binoculars: Zero-Shot Machine-Generated Text Detection* (Hans et al., 2024)
* **Core Idea:** Contrasts the perplexity of a candidate text evaluated under two closely related LLMs:
  1. **Performer Model ($M_1$):** A chat/instruct fine-tuned model (e.g., `falcon-7b-instruct` or `Llama-3-8B-Instruct`).
  2. **Observer Model ($M_2$):** A base pretrained model (e.g., `falcon-7b` or `Llama-3-8B`).
* **Formula:**
  $$\text{Binoculars}(x) = \frac{\log P_{M_1}(x)}{\text{PPL}_{M_2}(x)}$$
  Or normalized cross-perplexity score:
  $$S(x) = \frac{\frac{1}{|x|} \sum_{i=1}^{|x|} \log P_{M_1}(x_i \mid x_{<i})}{\exp\left(-\frac{1}{|x|} \sum_{i=1}^{|x|} \log P_{M_2}(x_i \mid x_{<i})\right)}$$
* **Why It Works:** Machine-generated text resides in high-density regions of both base and instructed models, whereas human text exhibits distinctive perplexity divergence between the two.
* **Advantages:**
  * Ultra-low False Positive Rate (FPR < 0.01% on academic benchmarks).
  * Robust against unseen LLMs and domain shifts without any retraining.
* **Requirements:**
  * Requires GPU memory sufficient to load two 7B/8B models (or sequentially run them with 16GB VRAM, or quantize via 4-bit `bitsandbytes`).

```python
# Quick Usage with Binoculars library
from binoculars import Binoculars

bino = Binoculars(observer_model_id="tiiuae/falcon-7b", performer_model_id="tiiuae/falcon-7b-instruct")
score = bino.compute_score("Văn bản cần kiểm tra...")
prediction = bino.predict("Văn bản cần kiểm tra...") # Returns "AI-Generated" or "Human"
```

## 2. Fast-DetectGPT (High Throughput / Production API)

* **Repository:** [baoguangsheng/fast-detect-gpt](https://github.com/baoguangsheng/fast-detect-gpt)
* **Paper:** *Fast-DetectGPT: Efficient Zero-Shot Detection of Machine-Generated Text via Conditional Probability Curvature* (Bao et al., 2023)
* **Core Idea:** Upgrades Stanford's DetectGPT by eliminating the slow perturbation step. Instead of generating 100 perturbed texts using a mask-filling model (like T5), Fast-DetectGPT directly computes the curvature of conditional probability under a single scoring model (e.g., GPT-2-XL, GPT-Neo-2.7B, or LLaMA-2).
* **Speedup:** **~340x faster** than DetectGPT (~2 ms per query instead of several seconds).
* **Formula:**
  Measures the discrepancy between the conditional likelihood of the actual token and the expected conditional likelihood over the model's predictive distribution:
  $$\tilde{\mathbf{D}}(x) = \frac{1}{|x|} \sum_{i=1}^{|x|} \left( \log P(x_i \mid x_{<i}) - \mathbb{E}_{y \sim P(\cdot \mid x_{<i})}[\log P(y \mid x_{<i})] \right)$$
* **Best For:** High-throughput production APIs, real-time backend scanning.

## 3. DetectGPT (Stanford Foundation Method)

* **Repository:** [eric-mitchell/detect-gpt](https://github.com/eric-mitchell/detect-gpt)
* **Paper:** *DetectGPT: Zero-Shot Machine-Generated Text Detection using Probability Curvature* (Mitchell et al., Stanford, 2023)
* **Core Idea:** Hypothesizes that text generated by an LLM typically occupies local maxima of the model's log probability function. Perturbing an AI passage slightly (e.g., swapping a few tokens) causes a sharp drop in log probability, whereas perturbing human text produces unpredictable shifts.
* **Limitation:** Computationally prohibitive for interactive web applications because it requires 50–100 masked perturbation passes through T5 per input query.

## 4. GLTR (Giant Language Model Test Room)

* **Repository:** [HendrikStrobelt/detecting-fake-text](https://github.com/HendrikStrobelt/detecting-fake-text)
* **Collaboration:** MIT-IBM Watson AI Lab & Harvard NLP (Gehrmann, Strobelt, Rush)
* **Core Idea:** Token-level predictive ranking visualization. For every token in the passage, GLTR checks its rank in the model's predictive distribution:
  * **Green (Top 10):** Highly predictable word choice (typical of AI text).
  * **Yellow (Top 100):** Probable word choice.
  * **Red (Top 1000):** Creative or less expected word choice.
  * **Violet (> 1000):** Unlikely word choice (strongly indicates human creativity or domain jargon).
* **Best For:** Explainable Generative UI, interactive writing assistants, student paper review panels where visual evidence of specific AI-generated paragraphs is required.
